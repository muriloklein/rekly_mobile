Atividade 01

Plataforma, IDE e emulador

  • Android Studio é a IDE oficial do Google, baseada no IntelliJ IDEA (da JetBrains). Antes se usava o Eclipse com o plugin ADT.
  • SDK: ferramentas e bibliotecas para criar apps. Cada versão do Android tem um nível de API.
  • Gradle: compila o projeto e gera o APK.
  • AVD (Android Virtual Device) é o emulador. É criado no Device Manager (antigo AVD Manager), escolhendo o modelo do aparelho e a versão do Android.
  • Celular real: ativar as Opções do desenvolvedor (tocar 7 vezes em "Número da versão"), ligar a Depuração USB e conectar o cabo. A comunicação é feita pelo ADB.
  • Emulador testa várias telas e versões sem ter o aparelho, mas é mais pesado. O celular real mostra desempenho e sensores reais.
  • Emulador oficial do SDK: Android Emulator. BlueStacks, GenyMotion e Android X84 são de terceiros; Virtual Box é virtualização genérica.
  • Linguagem nativa: no gabarito da UA é Java. Swift é a do iOS. Kotlin é a recomendada hoje (ver Atividade 02).
  • Ferramentas da IDE: break point pausa a execução para ver variáveis; monitor de recursos mede memória e processamento; verificador de sintaxe acha erros de escrita; versionamento (Git) permite trabalho em equipe; plugins adicionam funções de terceiros; renderização de layouts mostra a tela enquanto você monta.

Estrutura do projeto e recursos

Pasta / arquivoPara que serve
src (java)Código-fonte em Kotlin ou Java
genOnde ficava o R.java gerado (projetos antigos)
resRecursos: textos, imagens, layouts, cores, menus
assetsArquivos brutos (ex.: um .json ou fonte). Não ganham ID no R; são lidos com AssetManager
bin / buildArquivos compilados e o APK gerado
AndroidManifest.xml"Ficha" do app: componentes, permissões, tela inicial
  • APK (Android Package): arquivo compactado que instala o app. Leva o código compilado (.dex), os recursos e o manifesto.
  • res/values: strings.xml (textos), colors.xml (cores), temas. res/drawable: imagens. res/mipmap: ícone do app. res/layout: telas em XML. res/menu: menus.
  • Idiomas: values/strings.xml é o padrão e values-en/strings.xml é o inglês, com os mesmos nomes. O Android escolhe pelo idioma do aparelho, sem mudar o código.
  • Classe R: gerada automaticamente, com um ID (número inteiro) para cada recurso. Nunca é editada à mão.

Atividade 02

Kotlin

  • Criado pela JetBrains (anunciado em 2011, versão estável em 2016). O Google o tornou oficial no Android em 2017 e hoje o recomenda como primeira opção.
  • Roda na JVM e é interoperável com Java: dá para usar os dois no mesmo projeto.
  • val não pode ser reatribuído; var pode mudar.
  • Inferência de tipo: val idade = 20 já é Int, sem precisar escrever o tipo.
  • Segurança nula: String não aceita null; String? aceita. ?. chama só se não for null; ?: (elvis) dá um valor padrão; !! força e pode gerar NullPointerException.
  • data class gera sozinha toString(), equals(), hashCode() e copy(). Com ela, == compara o conteúdo.
  • Funções podem ficar fora de classes (ex.: fun main()).
val nome = "Ana"          // String (inferido), não muda
var idade = 20            // Int, pode mudar
var apelido: String? = null
println(apelido?.length)  // imprime null, sem erro
val t = apelido?.length ?: 0   // 0

data class Produto(val nome: String, val preco: Double)
class Pessoa(val nome: String) {
    fun ola() = println("Olá, $nome")
}

  • Manifesto: declara as Activities (todas!), a tela inicial (MAIN + LAUNCHER) e as permissões (uses-permission). Permissões perigosas (câmera, localização, contatos) também são pedidas ao usuário durante o uso.
  • Segurança: princípio do privilégio mínimo. Cada app roda isolado e só acessa o que declarou.
  • Ciclo de vida:
onCreate→onStart→onResume(rodando)→onPause→onStop→onDestroy
  • onCreate: roda uma vez, quando a tela é criada. Nele vem o setContentView e depois o findViewById.
  • setContentView(R.layout.x) carrega o layout. findViewById(R.id.x) pega um componente do layout. finish() fecha a Activity e volta para a anterior.
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    setContentView(R.layout.activity_main)          // 1º carrega a tela
    val btn = findViewById<Button>(R.id.btnSair)    // 2º busca o botão
    btn.setOnClickListener { finish() }             // fecha a tela
}

Listas, Adapter e menus

  • ListView: itens um abaixo do outro, com rolagem. GridView: itens em grade (colunas com numColumns).
  • Adapter é a ponte entre os dados e a lista: pega cada dado e monta a view do item.
  • ArrayAdapter: dados de arrays ou listas. SimpleCursorAdapter: dados de banco (Cursor). Adapter personalizado: herda de BaseAdapter ou ArrayAdapter e sobrescreve getView() para desenhar cada item do seu jeito.
  • android.R.layout.simple_list_item_1 é um layout pronto do Android (um TextView por item). Note o android.R, e não o R do seu app.
  • Clique num item: setOnItemClickListener, que entrega a posição clicada.
  • Menu: criar a pasta res/menu → criar o XML com os <item> → inflar em onCreateOptionsMenu → tratar o clique em onOptionsItemSelected usando o itemId.
val itens = arrayOf("Atividade 1", "Atividade 2")
val adapter = ArrayAdapter(this, android.R.layout.simple_list_item_1, itens)
lista.adapter = adapter

override fun onCreateOptionsMenu(menu: Menu): Boolean {
    menuInflater.inflate(R.menu.menu_principal, menu)
    return true
}
override fun onOptionsItemSelected(item: MenuItem): Boolean {
    return when (item.itemId) {
        R.id.menu_sair -> { finish(); true }
        else -> super.onOptionsItemSelected(item)
    }
}
04/11

Intent explícita e implícita

  • Explícita: diz quem chamar, pelo nome da classe. Usada dentro do próprio app. Dados vão com putExtra e chegam com intent.getStringExtra.
  • Implícita: diz só a ação (e o dado, em forma de URI). O Android procura quem sabe fazer isso. Objetivo: desacoplamento.
  • Intent Resolution: o sistema compara a Intent com os intent-filters declarados no AndroidManifest.xml dos apps. Se mais de um servir, aparece o seletor (App Chooser).
  • ACTION_VIEW: abrir site (https://) ou mapa (geo:). ACTION_DIAL: abre o discador com o número, sem ligar. ACTION_CALL liga direto e exige permissão. ACTION_SEND: compartilhar. MediaStore.ACTION_IMAGE_CAPTURE: tirar foto.
// Explícita: abre a DetalheActivity levando um dado
val i = Intent(this, DetalheActivity::class.java)
i.putExtra("nome", "Ana")
startActivity(i)
// na DetalheActivity:
val nome = intent.getStringExtra("nome")   // "Ana"

// Implícitas
startActivity(Intent(Intent.ACTION_VIEW, Uri.parse("https://upf.br")))
startActivity(Intent(Intent.ACTION_DIAL, Uri.parse("tel:5499999999")))

val share = Intent(Intent.ACTION_SEND)
share.type = "text/plain"
share.putExtra(Intent.EXTRA_TEXT, "Olá!")
startActivity(Intent.createChooser(share, "Compartilhar com"))
